# 运行与恢复

## 状态含义

- 命令 `queued`：持久化完成，尚未执行。
- `blocked`：缺少身份、连接、授权、账号会话或适配器能力，需要处理对应缺口。
- `unknown`：外部可能已经生效，必须先对账；同一命令不再次写入。
- `succeeded`：已得到同一外部账号的实际 API/浏览器回读证据；写命令还需声明标签核验；发布还必须匹配绑定授权正文的SHA-256哈希。

Mock 运行不会把浏览器命令标为真实成功。16 个平台默认均未连接；登录交互代理未配置时返回明确缺口。提交回执只成为 `submitted/unknown`，不能作为发布完成证据。

## 持久调度

本地 worker 每轮将已持久化授权、到期的发布和广告动作交给浏览器队列；browser-runtime 每秒读取 queued 命令。生产组织来自 `BROWSER_SERVICE_ORGS` 的服务身份绑定，可用 `BROWSER_DISPATCH_ORGS` 进一步收窄；真实模式不接受未绑定组织。模拟默认只处理代码固定的演练组织。命令持久保存其模拟/真实模式，切换部署模式后不会升级旧命令。

缺少 OIDC、逐平台 hook、全局写入/发布/广告开关时，命令、动作和关联发布任务进入 blocked，并写入审计与缺失能力。补齐配置后应由操作人复核并创建新的授权动作，不能直接篡改 blocked/unknown 状态重发。queued 只表示等待消费；verified 只在同账号独立读回与正文哈希匹配后成立。

发布再次核对当前账号时区的批准窗口；浏览器租约与执行动作租约各有独立 fencing token。轮询恢复会把过期不确定写入转 unknown；不会选取 unknown 再提交。停止进程先停止计时器并等待本轮处理、关闭实际浏览器 context，然后关闭数据库。

## 浏览器与账号恢复

1. 先停止该账号的自动调度和登录接手，并停止旧浏览器容器。确认旧进程退出；不要仅凭数据库租约过期重开 profile。
2. 备份加密 profile 卷及其锁元数据。文件锁位于卷的 `locks/`，每账号一个锁、全节点两个 slot 锁；崩溃遗留锁保留，阻止另一进程使用活跃 profile。只在旧容器确认停止后，移走对应账号及相同元数据的 slot 锁；不要删除其他账号锁或清空全部 profile。
3. 调用 `createBrowserService(...).recoverExpired()`，使过期发布/广告命令进入 `unknown`，只读命令回到队列；旧 owner/fencing token/session version 的心跳和结果被拒绝。
4. 对 `unknown` 调用 `reconcile(commandId)` 创建只读对账命令。它关联原 command/action；没有实际回读时仍保留未确定状态，不盲目重试。核验后补记录，原外部动作不再写一遍。
5. 验证账号未撤销、适配器版本及会话版本仍一致。验证码或 MFA 转 `challenge_required` 暂停；由当前组织和用户绑定的受控登录会话恢复，完成后核验实际账号身份再递增 session version。

票据有效期 60 秒，只能原用户在同组织、同账号兑换一次。兑换后的交互总时长最多 900 秒；到期、用户撤销、当前成员角色失去操作权或会话版本变化后代理必须拒绝继续控制。票据仅首次响应，数据库只保存 SHA-256；请求幂等重放只返回资源 ID 与空票据。

## 本地数据库恢复

停止 worker 和浏览器后，用 PostgreSQL `pg_dump` 保存逻辑备份；保持数据库卷与备份路径私有。恢复到新测试项目/卷，完成迁移版本与组织隔离核验后再启动应用。原库保留到恢复验证结束。不要把生产数据导入公开演练环境。

`compose down` 保留卷，重建容器不会清除业务记录。运行 `init` 可重复准备开发数据，不代表重置全部记录。`down -v` 会删除本地持久数据，必须由操作人明确选择。

## 云恢复与停止

VM启动脚本不会自动格式化附加profile磁盘；首次部署必须明确初始化已确认的新空磁盘，恢复盘有异常文件系统时先检查并停止启动。Cloud SQL 备份/PITR 与浏览器磁盘每日快照在 Terraform 声明；恢复需新隔离实例，核验实际数据及已撤销账号不会复活。会话 profile 必须在浏览器安全关闭后再生成加密对象备份，不复制正在打开的 Chromium profile。

规则撤销、账号禁用、连接失效和预算门槛需立即阻止新外部写入。成本告警不等于全云账户硬停机。当前云计划未 apply，故没有实际云备份、告警或恢复成功证明。
