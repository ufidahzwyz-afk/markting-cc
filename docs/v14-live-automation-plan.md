对齐日期：2026-10-04（北京时间）。工程基线：`fadf0a42cacbdd9b466d1a24327e5e3f52dfd25d`；后续增量分支：`codex/v14-live-automation`。

## 业务目标与当前状态

按用户本次要求，开发优先完成 **真实来源变化 → 有证据的洞察 → 推荐选题 → 自动生成可编辑草稿**，再完成实际发布、百度执行和结果回读。每次交付以真实业务对象、来源和运行证据验收。

原 [泊冉 AI 市场运营业务方案 V1.4](https://docs.google.com/document/d/1XOQmrVNaQcZXiROM37VHvSeM0sea-f8cIv3FcWE1tuU/edit) 已重新读取：方向、资料和规则确定后，系统自动策划、生产、发布、取数、整理线索及优化；两人共享结果，补充事实、跟进客户和处理例外。原 [PRD 1.2](https://docs.google.com/document/d/1ZYwYNVEy3ykoIK_RqPrTGVEUxm78aGftMf_9i6KpEJE/edit) 的业务基线为 V1.4。

用户最新明确要求、已确认 V1.4 业务方案与 PRD 作为需求依据；补充资料中的旧逐条审批限制和旧行业排序不覆盖后续确认。运行事实必须由实际来源或账号回读证明。

Mac 安装与启动已通过：用户确认及本地「安装并启动泊冉系统」任务记录包含 ARM64 镜像、五个服务运行、管理台与 API HTTP 200、Chromium profile 2/2。此项计入环境验收。此前 264 项工程测试证明已有工程行为；真实来源、模型和平台执行的业务验收仍待完成。

V1 完成范围继续包括四源、真实模型和素材生产、16 个首批渠道逐账号实测、百度实际读写、共享线索、报告通知、Drive 回读、恢复演练和七个完整业务日对账。分阶段接通是实施顺序，不缩小这些范围。

## 四源的准确范围

| 来源 | 指定输入及持续读取 | 真实验收证据 |
| --- | --- | --- |
| 公开市场信息 | 经确认的 URL、关键词及采集周期，默认每日 | 实际网页变化、原文版本、来源定位和采集时间 |
| 竞品公开推广 | 独立配置竞品网站、公开广告、文章与活动，默认每日 | 公开变化、版本及定位；只记录公开可观察信息 |
| Mac 指定资料的 Drive 同步 | 指定并授权的 Drive 目录稳定 ID，首次清单及 changes 游标，默认每 15 分钟 | 实际文件修改和同步、新版本、范围覆盖；游标失效可恢复 |
| 指定 ChatGPT 沟通 | 指定且授权的会话/项目，由独立系统的受控浏览器持续读取，默认每 30 分钟 | 会话、消息、角色、时间、分支及覆盖定位；关闭用户浏览器后仍捕获新增，重启可恢复水位 |

成功无变化、读取失败、覆盖不全、过期及授权失效分别保存。人工复制、导出或重新上传保留为应急功能，不计作持续读取通过。模型 API 不授予 ChatGPT 历史访问权；ChatGPT 持续读取 POC 是明确上线门槛，首批即验证实际能力。

百度报表、内容效果和销售反馈是后续分析输入，不能替换上述四源。只有实测通过的来源可标记已接通；首条来源通过不代表四源完成。

## 第一阶段：真实变化到草稿

先选一条用户能主动修改、范围已授权的业务资料来源，优先考虑已同步的 Drive 资料。同时开发另外三类来源，尽早验证 ChatGPT 持续读取 POC。

首条输入已落实为用户指定的 Drive 资料目录与 DeepSeek，API 地址为 `https://api.deepseek.com`。用户提出 DeepSeek-V4-Pro 与 DeepSeek-V4.1-Flash 两个候选；推荐以 Pro 处理洞察、证据冲突和重要选题，以 Flash 处理日常草稿和平台变体。模型名称和任务路由使用配置，具体运行模型及参数保存到记录中，更换模型重跑评测。

已独立读取 DeepSeek 官方 [模型目录](https://github.com/deepseek-ai/deepseek-harness/blob/5badb15009ae1756c3afe0ae0cef1faafc290ccc/packages/llm/llm-deepseek/src/models.ts) 与 [适配器说明](https://github.com/deepseek-ai/deepseek-harness/blob/5badb15009ae1756c3afe0ae0cef1faafc290ccc/packages/llm/llm-deepseek/README.zh.md)：Pro 的目录 ID 是 `deepseek-v4-pro`，定位为复杂/质量关键任务且成本较高；V4.1 Flash 的展示名称为 `DeepSeek-V41-Flash`，目录 ID 为 `deepseek-flash`，支持文本和图片，Pro 目录为纯文本。这是建议性目录；账号可用 ID、请求协议、实际响应模型、上下文和 JSON 能力仍需在真实接入时核验。不能把官方 harness 的 Messages 配置直接当作本项目 API 能力已验证。

当前费率未从实时官方计价页核实，不沿用其他 Flash 版本的静态价格，也不预设中文营销质量结论。对同一批至少 10 组真实资料变化及草稿，比较证据准确性、业务适配、人工修改时间、耗时、usage 和实际费用。Flash 通过相应业务评审后承担日常批量；证据冲突、重要承诺或质量失败可按限额升级到 Pro。事实、公开许可和执行规则继续由服务端独立校验。

通过当前 Google Drive 连接已列出指定目录和直接子目录：资料具有多级目录，并发现 PPTX 文件。这里只核对了可列出的元数据，尚未完成全文提取、全部后代清单、增量游标或独立应用授权。真实 reader 必须递归限定目录范围，按文件类型提取正文并记录失败/覆盖；出现未确认业务或公开许可时登记提议和缺口。

1. 自动采集真实变化，持久保存实际原文、版本/哈希、时间、覆盖、定位与差异，事务产生 `source.changed`。
2. 服务端读取真实来源、当前业务主数据、已核实事实和有效规则，构造脱敏的不可变模型输入。记录实际 provider/model、提示词版本、输入/输出哈希、引用版本、tokens、耗时、费用依据和校验结果。
3. 真实模型生成非空洞察：发现、证据、事实/推断、目标客户、问题、推广关联、选题角度、优先级理由及缺口。来源中的指令作为资料处理，模型不能创建授权。
4. 服务端按 Schema v2 和语义约束验证后幂等落库。新提议由服务端分配持久 ID；确认或撤销必须定位用户明确表达，最新确认优先。
5. 候选主题进入现有主题工作区。按批准的确定性规则排序：P0/P1/P2、`priority_score=null`，同级按来源变更时间降序及稳定主题 ID 升序。成熟真实线索校准前不启用旧数值权重和阈值。
6. 规则内自动生成草稿及适用平台变体，保存主题、来源、逐段依据、CTA、缺口、生成运行和不可变版本。未核实或公开许可不足的事实留在私有候选稿/提议中；公开审核、素材和发布门槛继续独立验证。
7. 今日工作展示实际变化、已产洞察/草稿和待办；推广主题展示推荐理由、客群及证据；内容入口可查看、编辑草稿并追溯。沿用已确认的页面与人工功能。

来源更新产生新版本，保留人工修改版本；重复同步、重试或进程重启不重复产生同一业务对象。修正或撤销事实重检受影响待执行版本，保留既有生效结果的历史证据。

### 第一阶段的通过条件

| 实际场景 | 必须展示的结果 |
| --- | --- |
| 首次建立基线，再在真实资料中修改一个具体业务事实 | 配置采集周期内取得新版本、原文与变化；自动产出非空洞察、推荐主题和可打开编辑的草稿 |
| 查看该草稿的依据 | 能追溯到模型运行、主题、洞察、主张及实际来源版本/原文定位；显示真实模式和准确缺口 |

| 再发生一次真实修改 | 系统自动更新受影响内容，保留旧版本和人工稿；无需反复复制或手工新建主题 |
| 同版本重采集、重复任务、服务重启 | 水位恢复，同一变化不重复创建洞察、主题、草稿或排期 |
| 读取失败、部分覆盖、范围撤回、模型超时或非法输出 | 显示影响、负责人和恢复动作；失败不能写成无变化，未完成不能写成成功 |

首条真实纵向链路通过后，四类来源各发生一次真实变化并通过相同证据检查，验证四源路径。AC28 另验证用户明确确认、后续修正/撤销及助手总结不能冒充确认；AC40 另验证有效规则下高优先级主题填空槽、窗口/频次、过期不补发及已生效任务不改写。各场景取得真实证据后分别验收，不能仅凭四次变化宣布全部通过。周一 08:00 周计划继续遵循原 PRD。

AI 质量另设至少 30 个业务评测样例，覆盖用友、致远两条主线以及无证据、过期、公开许可不明、重复、缺数据、来源指令注入和数值错误；至多一次结构修复后 Schema 有效率 100%，硬性事实/安全用例全部通过。至少 10 份真实草稿由运营评审，模型自评分不能替代业务评审。

## 第二阶段：实际发布与百度生效

先用一个已授权账号和一个批准官网路径跑通发布，再扩展首批 16 渠道逐账号验收。每主题选适合的 1–3 种形式与批准账号组合；实际图片、视频、许可与平台风格齐备后，按持续规则自动排期。

成功必须包含目标账号、实际 URL/资源 ID、内容版本、审核状态、应有声明/标识和目标页面/资源回读。提交或审核中保留相应状态。官网发布保留现有站点和批准路径，localhost 结果不计作正式同域发布。

百度先接实际报表及业务必需粒度，搜索词只读并作为新增词/否词的依据；再贯通计划、单元、关键词、否词、创意、链接、地域/时段、出价与启停的逐对象执行。服务端取得前快照，匹配有效预算/频控规则，执行后回读生效字段、审核及复查；历史预算数值不作为当前授权。

结果未知先查询，确认未产生副作用后才恢复原动作。命令、action、publish job 和回执保持关联，重启、回执丢失或审核延迟不重复发布或变更。实际媒体、账号授权及停止开关持续检查。

随后完成咨询与共享线索、销售反馈、日报送达、Drive 回读及下一轮规则内优化，并取得 AC35 七个完整业务日证据。首轮集中批准范围内自动推进；新方向、新事实/承诺、预算增加和异常进入集中待办。

## 保留现有功能与数据

沿用当前 Compose 项目名及 PostgreSQL、媒体、browser profile 卷。开发和恢复演练使用隔离数据库；现有运行库不清空、不重建，也不执行删除卷操作。

Mac 已验证为本地测试宿主；原 V1.4 的持续运行目标保留。后续生产运行方式须满足用户浏览器关闭后继续任务，不能把只有 Mac 在线的试用结果写成独立云端持续运行通过。
