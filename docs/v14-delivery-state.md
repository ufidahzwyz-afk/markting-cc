本次分支为 `codex/v14-live-automation`。范围依据 [V1.4 目标](v14-live-automation-plan.md) 和用户确认的业务逻辑图；系统名称为泊冉。工程验证使用隔离数据库、合成材料和本地 HTTP/Chromium 服务，不能代替用户业务验收。

## 已落地的增量

- 四源独立范围配置、持续采集任务、原文与正文哈希、不可变版本和覆盖缺口。Drive 支持 OAuth 更新、授权目录后代清单、changes、删除撤回与过期水位恢复；网页读取校验 URL、DNS、重定向和大小；ChatGPT 使用固定配方与独立浏览器资料读取指定会话。
- DeepSeek 官方 HTTPS transport、可配置 Pro/Flash 路由、模型目录核验、证据与结构化输出校验、脱敏输入、实际模型/usage/请求回执与持久调用限额。日配额按北京时间计算；只有明确未发出请求的限流才排队恢复，已调用但结果未知的任务不会再次付费调用。
- 来源变化 → 有依据的洞察 → 推荐主题 → 私有可编辑草稿已接入持久工作流。新资料变化追加生成版本，人工编辑版本与旧来源保留。实际回执先持久化，再落业务对象，重启可恢复而不重复生成。撤销事实使相关待执行对象失效，保留已有结果的历史证据。
- 今日工作、推广主题和内容入口展示变化、证据、缺口与真实/模拟模式；原人工台账继续使用。模型与来源配置从后台完成。
- 网站及渠道用户名、密码、API Key 和 OAuth 凭据进入本地 AES-256-GCM 加密存储，数据库只保存绑定组织与连接的引用。密码连接选择固定服务端适配器后自动排队登录；实际账号身份回读成功后才可启用。轮换凭据会撤销旧会话与旧命令。
- 已建立受控二维码/单字段验证码交互、实际身份回读、发布提交与审核等待、结果未知后的只读查询及百度固定端点的读写框架。网站单独配置；首批 15 类内容渠道加百度仍为 16 个。
- 本地真实读取有独立成员登录、内部短期服务身份、私有卷及受限出站；新增 003–005 迁移保留 001/002 和旧数据。升级前备份包括数据库、媒体、浏览器资料、来源原文及解密密钥，恢复验证使用独立临时数据库和卷。

## Mac 升级与配置顺序

1. 用 [私有备份与升级说明](mac-live-readonly-and-credentials.md) 完成备份及隔离恢复检查，再获取本次分支；使用原 Compose 项目和数据卷。
2. 启动真实读取 overlay，按 [本地成员登录说明](local-live-login.md) 为原有有效成员设置独立登录密码。不要清库、重建用户或删除卷。
3. 后台保存来源授权范围与凭据、DeepSeek 模型配置、业务事实和当前有效规则；先验证实际来源变化到私有草稿。
4. 逐网站/渠道配置固定适配器与账号；自动登录遇到扫码或验证码时本人完成一次。真实身份验证、账号启用、发布能力和执行授权分别验证。
5. 取得真实发布、百度执行及结果回读证据后，再开展效果、线索、报告和连续业务日验收。

本次统一回归 444/444 通过、无失败或跳过；10 个工作区类型检查及两个应用生产构建通过。实际 Chromium 桌面/手机界面三轮共 104 项检查通过；数据库、HTTP、并发与重启恢复使用隔离工程环境验证。

当前代码未自动升级用户 Mac，也未配置真实账号或打开发布/付费变更开关。工程检查的公开汇总见 [最终联调记录](acceptance/v14-integration-checks.json)，业务材料、凭据和原始草稿留在私有存储。
