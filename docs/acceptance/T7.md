# T7 复盘、通知与 Drive 归档

状态：报告及可靠交付控制已实现并通过隔离测试；真实来源、通知、Drive、七个完整业务日与最终闭环 **blocked / 尚未验收**。

## 已实现

- `packages/domain/src/reporting.ts` 生成不可变日报/周报快照。数字来自确定性指标，执行状态复制已持久证据，不接受模型或客户端宣称的执行成功；同内容重复调度复用版本，数据修订形成 r2，保留 r1 及来源批次。
- 模拟/真实报告分开查询。SEO 缺来源/证据保持 unavailable；零分母返回 null，排名按实际曝光加权。GEO 保存平台、模式、地域、消息、时间及原始引用，失败采样不补造；只有实际有效采样进入分母，未复核不输出命中率，不同模式不混算。
- 每报告/渠道/目的地唯一通知，与 outbox 同事务写入。发送前持久 unknown 意图与租约；超时先对账，仅明确 absent 才重发；有限退避与尝试上限，失败记录和告警事件保留。旧尝试不能覆盖新通知结果。
- `apps/worker/src/report-dispatch.ts` 消费 `report.ready`，为活跃 owner/marketer 两位运营成员持久化 `in_app` 及 email 交付意图。站内收件箱以 `user:<uuid>` 定位本人，真实数据库行回读成为站内送达凭据；重复/并发调度不重复通知。私有进程 registry 按组织与模式配置可信通知/Drive 适配器，公开 HTTP 不接受适配器、凭据或 receipt。
- 无外部通知/Drive 适配器时，outbox 保持未完成，payload 标明 `needs_human`、错误代码和缺项，保留 pending 状态与后续恢复；不计提交尝试、不虚报外部送达或归档。注册可信适配器后沿原事件执行领域的租约/unknown/回读对账协议。
- 每次新的 live 外部通知发送和 Drive 写入前，重新检查部署 `WRITE_ENABLED=true` 与当前组织 `write_enabled=true`；任一关停即 pending，并持久 `needs_human / WRITE_DISABLED` 缺口，不计提交尝试、不伪造 unknown/成功。站内数据库通知及已发生结果的只读 reconcile/find/read 继续；confirmed absent 后的新写再次检查开关。租约使用独立单调 `leaseGeneration` 加尝试计数复核，停写恢复计数不复用 fence，旧 worker 迟到不能覆盖待处理状态。
- Drive 写入使用稳定报告版本键；重试先找已有文件，未知结果不盲目重写；内容 SHA256 与真实版本回读匹配后才 `archive_status=succeeded`。失败保留 pending event/告警并有限重试，旧尝试不能覆盖新归档结果。
- 七业务日完整度按实际业务日期与全部配置账户检查；Mock 或历史 CSV 不计真实验收。
- 广告档案结束时间为空不可清理；至少保留传播结束后三个日历年，法律保留期间不删除。PII 使用独立策略。结束记录版本控制并审计。
- 独立指标策略版本：去重初始 30 天，归因/成熟窗口初始 null，定性评分；草稿不启用。owner 按精确 hash 批准；数值校准须定位组织内实际销售确认线索，测试数据不能充当校准样本。批准配置仍不能替代实际数据门槛。

## 真实验收缺口

- AC24/33：站内通知现在有实际数据库收件箱记录及回读；尚无实际外部通知/Drive 适配器账号，不能证明两人收到邮件/外部通知或真实 Drive 归档读回。失败告警已持久，主动外部告警送达仍需授权渠道联调。
- AC16：GEO 真实平台/模式采样尚未接通；SEO 目前提供确定性计算入口，真实采集器与证据持久注册仍待接入，不能展示虚构排名。
- AC35/43：未取得同 cohort 可归因真实线索，paid CPL 与自动效果调优保持 unavailable。指标策略的批准不自动赋予百度执行权限。
- 七个完整业务日、共享线索销售反馈、实际优化进入下一轮计划、广告实际发布/下线证据仍需真实集成验证。广告初始档案由内容/发布流程写入，本模块只管理结束和保留条件。

线索持久化与 `lead.created` outbox 属 T6；本模块的 report 通知不修改或删除线索，通知失败不会撤销原始入库。直接线索通知消费者需与 T6/worker 联调，不能将报告通知当作所有接待通知已完成。
