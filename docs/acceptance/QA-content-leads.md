2026-10-03，由 T6 实施者独立验收 T3 内容与匿名官网入口；问题交给对应模块负责人修复后再回归。验收数据库为隔离组织的 PGlite，HTTP 读回使用真实临时 Node HTTP 服务及共享 SSR 组件；这部分不能代替正式域名和实际 Next 部署验收。

`node --import tsx --test --test-concurrency=1 packages/domain/tests/leads.test.ts packages/domain/tests/reception.test.ts tests/integration/content-leads.test.ts`：23/23 通过（T6 17、交叉集成 6）。`npm run typecheck --workspace @boran/domain` 通过。

| 独立检查 | 发现与修复 | 最终结果 |
| --- | --- | --- |
| 匿名草稿/历史版本 | 开发预览曾依赖环境标志并构造 owner；公开预览改为始终 404，草稿只走已鉴权 API | 已发布读只取当前 release；回滚恢复实际正文和 canonical，旧版本仍保留 |
| 当前访问权限 | 内容入口曾信任缓存角色；所有相关入口与写事务重验当前有效成员 | 停用成员即使保有 owner 缓存角色，也不能读取私有预览 |
| 实际页面读回 | 仅凭正确 data 标记与任意 H1 会误判；加入精确 H1、可抓取模块正文、媒体及有效表单检查 | 伪造正确标记但缺正文的 HTTP 响应被拒；mock 证据不变成真实 succeeded |
| 媒体许可 | 公共投射与下载入口许可条件曾不一致 | 均要求实际媒体与非空许可证据；缺少许可的媒体不进入公开投射 |
| 隐私接收门槛 | T3 最初使用不同 approved 字段，改用 T6 共享 gate | 完整 owner 配置、合法基础及受理流程仍须服务器显式开启 mock 表单，客户端不能启用真实采集 |
| 匿名 JSON 边界 | cast 未进行完整 schema 校验，null 会产生错误状态 | schema 严格校验后 null/未知字段返回通用 400，不回显个人信息 |
| 表单与线索分层 | 按模块提交文案保持 HTTP 读回一致；咨询许可和营销 opt-in 分开 | 默认表单关闭且营销不预勾；确认可联系与企业意图后才创建线索；两运营旧版本修改 409 |
| 页面 CTA | contracts 曾拒绝业务支持的 #lead-form | 精确锚点可通过；同页必须有表单；#admin 和其他锚点仍拒绝 |
| 默认阻断与重试 | 检查默认隐私关闭、蜜罐、旧 release 和重复 receipt | 禁止请求不产生留资；合法重复请求回同一 receipt；一次确认保留当前来源业务线 |

交叉验收另推动 T6 配置加固：严格白名单拒绝隐藏密钥字段和客户端批准字段；限制文本长度与字段类型；批准者和受理人的 users/memberships 活跃性在每次 live 接收前重新检查。T3 实施者另用隔离数据库复现并独立验证三种停用情况均阻断。

实际 Next HTTP、浏览器桌面/移动页面和共享操作的记录见 `QA-ui.md`。正式域名路径、实际媒体授权、爱番番首答送达 ≤3 秒、真实下游删除/导出和广告接入仍需对应真实连接与证据，不算上述本地通过项。
