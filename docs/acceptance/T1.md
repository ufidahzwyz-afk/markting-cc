# T1：数据库、执行核心与持久工作流

已实现 60 张规格业务表及独立迁移账本，PostgreSQL/PGlite 双驱动，同组织复合外键、UUID 数组引用校验、状态/摘要检查、不可变载荷与追加审计。首次 baseline 为 001，002 补充批准版本组织外键与 active 规则批准约束；已验证实际 PostgreSQL 17；部署后不得修改已应用迁移文件。迁移以 SHA256 校验上下行文件、事务表锁串行执行。回滚为显式 `tsx packages/db/src/migrate.ts --down`，会删除该版本数据，先备份；不在启动时回滚。

本地数据库默认 `.local/postgres`，进程内共享一个串行连接，磁盘 writer lock 拒绝第二个进程；多进程部署使用 `DATABASE_URL` 的 PostgreSQL。`initialize:false` 不执行 migration 或 seed，已有库缺失时启动失败。匿名种子只有模拟组织及两名人员，不导入原始业务文件或真实联系人，不创建平台凭据；组织 `write_enabled=false`。

执行核心支持当前组织成员角色并集、服务不能自批规则、owner 激活与撤销、单次批准消费、规则版本复核、事务动作幂等、预算与发布频次预留、账号时区的日/周频次及发送时发布窗口、租约 fencing。提前排期允许保存，实际发送的时窗/账号范围失效即持久 blocked；mock 不绕过，单次批准免持续规则窗口。意图与 outbox 先持久化后才交由适配器执行；已提交或 unknown 不可再次 claim。租约过期外部动作进入 unknown，只能对账。模拟输出不记录真实 succeeded。真实广告 gate 依赖私有适配器持久化的近期原生预算回读以及完整 live connector 批次，CSV、模拟批次与 API 自报证据不能成为执行证明。

持久工作流按步骤 ordinal 执行，领取使用 `FOR UPDATE SKIP LOCKED`，5 分钟租约、30 秒心跳，成功步骤不重做，重复调度返回原 run。worker 仅有健康端点，无未经鉴权的 dispatch；注册的 mock/read-only handlers 可以扩展，外部写步骤过期进入 unknown + needs_human，不自动重发。

ops 执行 handler 接入规则、版本、批准、动作、人工凭据、运行详情与任务 CRUD。组织级 GET 从当前会员表复核 owner/marketer，拒绝纯 sales 或过期角色；brief 递归检测联系方式与凭据，包含 NFKC 与百分号编码，不保存或回显原文，保留合法引用/摘要。写命令使用根路由的身份/CSRF/幂等/版本控制；人工凭据只能成为 externally_completed；公共对账接口没有可信已接通适配器时返回 503，不接受客户端自报成功。

独立验证：

- PGlite：4 个数据库测试、9 个执行核心测试、4 个 worker 测试、4 个执行/任务 API 测试通过，覆盖 migration 哈希/回滚、跨组织保护、追加审计、持久打开、角色提升、规则撤销、并发幂等/预算、北京时间 00–08 日界、发送窗口延迟/账号/weekday/时区/单次授权门槛、编码凭据拦截、旧租约拒绝、unknown 禁止重发、成功步骤不重做、未注册 handler 进入 needs_human 而不伪造完成。
- 实际 PostgreSQL 17：2 个驱动测试与 T5 独立 12 个恢复/授权/时窗测试通过；隔离临时 schema 验证多连接 `SKIP LOCKED` 跳过被另一事务锁住的步骤、失败事务回滚。使用 `BORAN_TEST_PG_URL` 启用，不输出凭据，测试结束删除临时 schema。
- 数据库、domain、worker 及 ops TypeScript 检查通过；跨模块与最终 HTTP 集成由根代理继续执行。

这些验证是本地运行能力与数据库语义验证，真实发布、广告写入、平台登录与私有业务资料读取尚未验收。
